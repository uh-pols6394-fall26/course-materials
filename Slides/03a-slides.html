What GitHub adds

Git works on your laptop, even offline. A local commit saves a version there; it doesn’t send a copy anywhere else.

GitHub gives us:

  • An online copy of the commits you push, available if your laptop fails
  • A shared place to deliver lessons and submit work
  • A website where we can read files and compare changes

Git can work with other hosts too. We’re using GitHub for this course.

Identify and Authenticate

RStudio’s Console and Terminal

  • The Console runs R code. Its prompt is >.
  • The Terminal runs shell programs, including git and gh.
  • RStudio puts the Terminal inside the IDE; it does not translate the shell’s commands.

The Terminal lets us ask the computer where we are, see which files are there, and run tools that do not have RStudio buttons.

Linux: do nothing

RStudio opens a standard Linux shell.

  • Leave the default Terminal setting in place.
  • The commands in this lesson will work as shown.
  • Linux paths use forward slashes, such as /home/name/course-project.

Mac: do nothing

RStudio opens the Mac’s default shell, normally zsh.

  • Leave the default Terminal setting in place.
  • The commands in this lesson will work as shown.
  • Mac paths use forward slashes, such as /Users/name/course-project.

Windows: choose Git Bash

Git Bash is a Unix-style shell supplied with Git for Windows. It gives Windows the commands and path conventions used in this lesson.

Choose Tools → Global Options → Terminal → New terminals open with → Git Bash. Click Apply, then open a new Terminal.

Git Bash uses your Windows programs and files. A Windows path such as C:\Users\Name appears as /c/Users/Name.

Find where the Terminal starts

Run one line at a time:

pwd
ls
  • pwd means print working directory. It prints the folder where commands will act.
  • ls means list. It prints the files and folders inside that directory.

Read the two results before continuing. Before cloning, you may see your home folder and personal files. The course folder doesn’t exist on your laptop yet.

Check the two programs

In RStudio, open the Terminal tab, usually beside the Console. If it is not visible, choose Tools → Terminal → New Terminal. Run one line at a time:

git --version
gh --version
  • git and gh name the programs.
  • --version asks each program to identify itself.

A version number means the program is ready. Leave the first error visible if either command fails.

Identity and authentication are different

Git identity is the name and email written on your commits.

GitHub authentication proves that this laptop is allowed to use your GitHub account.

We check both. Signing into the GitHub website does not automatically configure either one in RStudio’s Terminal.

Check what Git thinks

git config --global user.name
git config --global user.email
  • config reads a Git setting.
  • --global means the setting applies across your account on this laptop.
  • user.name and user.email name the two settings.

If both answers are correct, leave them alone.

Set Git’s identity only if needed

Replace the examples with your name and the email attached to your GitHub account:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

The quotation marks keep a name or address together as one value. These commands do not sign you into GitHub.

Run the two check commands again and confirm what Git prints.

Why we use GitHub CLI to sign in

Authentication tells GitHub which account is connecting and whether it can access a private repository.

One short Terminal command, gh auth login --web, starts a browser sign-in. You approve access on GitHub; gh stores the credential.

Then gh auth setup-git lets Git use that login, including through RStudio’s Git buttons. You don’t have to create and copy a personal access token yourself.

Sign in with GitHub CLI

gh auth login --web --git-protocol https --clipboard
  • gh auth login begins GitHub authentication.
  • --web uses GitHub’s browser sign-in.
  • --git-protocol https selects the connection used in this course.
  • --clipboard copies the temporary sign-in code for you.

No personal access token needs to be created or pasted into a file.

Finish in the browser

  1. Your browser opens GitHub’s device-login page.
  2. Paste the temporary code when GitHub asks for it.
  3. Confirm the account name carefully.
  4. Authorize GitHub CLI.
  5. Return to RStudio’s Terminal after GitHub reports success.

The temporary code is for this login only. It is not your password.

Connect Git and check the account

Run these separately:

gh auth setup-git
gh auth status
  • setup-git tells Git to use GitHub CLI’s stored credential when it contacts GitHub.
  • status reports the GitHub account currently recognized on this laptop.

That’s authentication finished. Next we’ll clone once in the Terminal and open the project. After that, we’ll use RStudio’s Git buttons.

Clone Once

Clone means make the working copy

Your repository already exists on GitHub. Cloning downloads its files and Git history to your laptop.

Do this once. After today, reopen the same RStudio project rather than cloning it again.

We’ll clone in the Terminal, then open the project in RStudio.

Clone in the Terminal

Replace YOUR-USERNAME with your GitHub username:

gh repo clone uh-pols6394-fall26/course-YOUR-USERNAME

gh repo clone downloads the repository. The slash separates the organization from your repository name.

The new folder appears in the Terminal’s current directory. Choose File → Open Project, enter that folder, and open pols6394.Rproj.

Watch this demonstration. You’ve already cloned your repository.

RStudio’s clone route: watch only

After gh auth login and gh auth setup-git, RStudio uses the same authentication.

  1. Choose File → New Project → Version Control → Git.
  2. Paste the HTTPS URL you just copied into Repository URL.
  3. Set the parent directory to a folder such as Documents/POLS 6394.
  4. Click Create Project.

RStudio clones the repository, opens it as a project, and switches to it.

Don’t do this now. A second clone would leave you with two copies to confuse. Keep using the project you already opened.

If a box asks for a username

Cancel it. GitHub account passwords won’t authenticate a clone.

The box means the sign-in didn’t take. Go back to the Terminal, run:

gh auth status

Check that it names your account, then run gh auth setup-git before retrying.

Check the project

Open RStudio’s Terminal and run:

git status

A successful clone should report:

On branch main
nothing to commit, working tree clean

main is this repository’s default branch. A clean working tree means your local files match the latest commit.

Confirm RStudio sees Git

Before using the Git buttons:

  1. Open Tools → Project Options → Git/SVN.
  2. Confirm that Version control system is set to Git.
  3. Close Project Options.
  4. Find the Git tab in the Environment–History–Git pane.

If the tab is missing, close and reopen this RStudio project. Restarting R alone does not reload the project controls.

Inspect before committing

git status
git diff

git status names changed files. git diff shows the changed lines that have not yet been staged.

Read the file list before you commit. A token, password, .Renviron, or unrelated personal file should never appear there.

Commit with RStudio

  1. Open the Git tab.
  2. Check Staged beside 03a-workbook.qmd.
  3. Click Commit.
  4. Enter Complete Workbook 03a.
  5. Click Commit, then close the commit window.

Staging chooses the file for this commit. The message records what the commit accomplishes.

The RStudio Terminal version

These familiar commands perform the same commit:

git add .
git commit -m "Complete Workbook 03a"

git add . stages changes under the current project folder. git commit -m records them, and the quoted text supplies the commit message.

Use either the RStudio buttons or these commands, not both for the same commit.

Your commit is still local

At the top of the Git pane, look for:

Your branch is ahead of ‘origin/main’ by 1 commit.

Your project has one saved commit that hasn’t been sent to GitHub.

origin/main records the GitHub branch as of the last synchronization. Push sends your commit; the “ahead” message should then disappear.

Push the commit

Click Push in RStudio’s Git pane. The RStudio Terminal equivalent is:

git push

push sends your local commits to your private repository on GitHub.

If Something Fails

Stop at the first error

  1. Stop typing commands.
  2. Read the first error message.
  3. Leave RStudio’s Terminal visible.
  4. Ask Amanda or me.

Common cases:

  • command not found: Git or GitHub CLI is not available to RStudio’s Terminal
  • a username box appears: the sign-in didn’t take; check gh auth status
  • authentication failed: GitHub CLI is not connected to the expected account
  • repository not found: the URL, invitation, or repository permission is wrong
  • not a git repository: RStudio’s Terminal is in the wrong folder
  • nothing to commit: the file was not saved or did not change

Mini-project 2: recover an uncommitted edit

Begin only if git status reports a clean working tree.

  1. Open README.md, add TEMPORARY TEST — remove me below its title, and save.
  2. Find the modified README.md in the Git pane and click Diff.
  3. Confirm that the diff shows only the temporary line.
  4. Select README.md and choose the Git pane’s Revert command. It may be under More.
  5. Confirm the warning, then check that the line disappears and the Git pane is clean.

Revert discards an uncommitted edit. Here we use it only on a change made for this exercise.
